# 2026-11-28 三厂商回收与地址池修正

## 修正后的行为

- 厂商二地址池改为 **192.168.140.51–192.168.140.250，共 200 个地址**，对应在原 .76–.225 两侧各增加 25 个。网关与掩码保持现场既有配置。
- 地址核对改为每 20 秒触发。自动检测候选采用“厂商完整清单没有 IP 占用 + 没有其他活跃 MP 场景关联 + 地址可达性检查无应答”的现场口径。每轮轮转检测最多 16 个候选，避免一次性检测整段地址使任务长时间阻塞；创建资源前仍有即时核对/按需检测。调度与分配恢复共享本进程锁，数据库条件更新保护多实例并发。
- 原有 40 条 `INITIAL_UNREVIEWED` 不再永久等待人工放行。符合以上条件后转成 `FREE/PROBE_CONFIRMED_FREE`；IP 仍出现在厂商清单、存在其他活跃场景关联、仍可达或检测异常时保留状态。
- 厂商二旧版资源已有准确场景节点 UUID 关联、场景进入删除而资源已从完整清单消失时，可以完成历史回收确认，避免要求重新观察已删除虚拟机。资源回收与 IP 重用分别确认：可达性检测暂不可用或 IP 仍有占用时保持地址隔离，后续核对符合空闲条件再释放。
- 厂商二/三的历史节点既无 UUID/VMID 又无台账时，成功读取完整清单后完成本地节点删除并记录告警。该分支不向厂商发送空 ID，不猜测其他 VM 的归属；有未结案创建/资源台账时仍使用台账核对。没有原始关联的厂商资源不能据此断言已经删除，应通过告警和实际资源清单追踪。
- 厂商一新增持久化创建台账：调用厂商前记录唯一请求名称和场景节点关联，创建响应丢失时保留原请求，再次创建或回收时可按准确名称恢复 UUID，避免重复提交及丢失关联。直接资源管理接口与场景创建共用原 API，场景创建通过新台账入口执行。
- 新增异常删除场景重试任务，每分钟检查前台实例已标记关闭、没有任何仍活跃的实例、MP 场景仍 DELETE/ABNORMAL 且至少一分钟未更新的记录。通过正常场景逻辑删除流程重试；每轮最多 8 个，单场景至少间隔 5 分钟，持久化领取防止多实例重复排队。不会直接把异常事件的状态 SQL 改成成功。
- 既有每小时三厂商残留资源兜底回收继续运行，厂商一新增台账也可恢复已关闭场景的 UUID。厂商三仍核对 VMID 和原始唯一名称，避免历史重复 VMID 导致误删。

## 发布及数据库

本次新增 MySQL/MariaDB、DM 对应迁移：

```text
mp/src/main/resources/db/migration/V202611280900__vendor_reclaim_recovery.sql
mp/src/main/resources/db/dm/V202611280900__vendor_reclaim_recovery.sql
```

新增 `mp_vendor_first_vm_ledger`（厂商一创建关联及历史记录）和 `mp_vendor_scene_delete_retry`（异常删除重试领取记录）。应用已有的 Flyway 升级流程会创建这些表；现场禁用自动迁移时，随本次代码应用对应数据库脚本。已有厂商二地址池和厂商三 VMID 台账不用清空或重新建表。

现场如存在显式旧环境配置，须同步更新：

```text
XD_TWO_IP_POOL_START=192.168.140.51
XD_TWO_IP_POOL_END=192.168.140.250
XD_TWO_IP_ON_DEMAND_PROBE_RANGE=192.168.140.51-192.168.140.250
```

默认可达性检测启用，单地址等待 1000 毫秒。显式禁用探测或把专属检测范围设为空，会保留地址自动核对的关闭状态；本次不会强行覆盖显式环境配置。新的调度周期随 MP 重启加载。

## 核查日志与数据

部署后可查：

- `厂商二地址自动核对`：本轮候选数、实际检测数、新增 FREE 数。
- `厂商二完整清单无占用且地址无响应，转为可用`：已自动恢复的地址。
- `厂商二已确认资源不存在，释放`：完成资源回收后已释放地址。
- `历史节点无UUID` / `历史节点无VMID`：仅完成本地收尾、未发出物理资源删除的历史节点。
- `重试已关闭实验的厂商场景回收`：已提交正常删除重试的场景。

```sql
SELECT status, reason, COUNT(*) FROM mp_vendor_second_address_pool
GROUP BY status, reason ORDER BY status, reason;

SELECT scene_id, element_id, vm_uuid, status, updated_at
FROM mp_vendor_first_vm_ledger;

SELECT scene_id, attempts, updated_at FROM mp_vendor_scene_delete_retry;
```

测试采用模拟厂商响应和 H2 事务数据库，覆盖旧版 UUID 已消失、40 条初始候选分批转 FREE、检测异常/占用隔离、并发状态变化、创建结果丢失、厂商一台账在事务回滚及进程重建后保留，以及仅重试前台确已关闭的异常场景。现场无法直连，本地测试不等于现场部署验收。
